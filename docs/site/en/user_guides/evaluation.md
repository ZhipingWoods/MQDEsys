# Dataset evaluation

MQDEsys separates two evaluation layers to distinguish datasets that can run locally from those provided as catalogue entries:

1. **Offline benchmarks**: load the checkpoint directly and score it with the built-in evaluator; no serving backend is required.
2. **EvalScope datasets**: executed through the official EvalScope CLI and its datasets; the model must first be served behind an OpenAI-compatible endpoint.

## Offline benchmarks

Three benchmarks are defined in `data/datasets/benchmarks.yaml`:

| Name | Kind | Metric | Purpose |
|---|---|---|---|
| `wikitext2_ppl` | PPL | perplexity | Uses the same window protocol as the quantization report, so before/after runs are comparable |
| `smoke_qa` | QA | accuracy | Short question answering; quickly verifies checkpoint usability |
| `smoke_mcq` | MCQ | accuracy | Answer log-probability scoring without a generative judge |

Offline benchmarks can be used by evaluate-only jobs and by the evaluation stage of a full pipeline. They do not require vLLM, SGLang or llama.cpp.

## Native dataset runner

The framework includes an in-process dataset runner covering:

- GSM8K: generative answering with numeric answer extraction;
- MMLU: multiple-choice log-probability;
- ARC-Challenge: multiple-choice;
- HellaSwag: continuation selection;
- Winogrande: coreference selection.

These tasks load Hugging Face datasets through the optional `datasets` package and normalize and score rows in `python/mqde/eval/native.py`, without lm-eval or the EvalScope CLI. If `datasets` is not installed or a dataset cannot be loaded, that benchmark is marked failed in the report without affecting the rest of the job.

## EvalScope catalogue

`data/datasets/evalscope_catalog.yaml` is generated by `scripts/gen_evalscope_catalog.py` from EvalScope's supported LLM dataset list. It contains 144 datasets with name, display name, category and tags. The file is a **metadata catalogue**; EvalScope performs the actual run.

Categories include:

- Knowledge and reasoning: MMLU, MMLU-Pro, C-Eval, CMMLU, ARC, HellaSwag, GPQA-Diamond;
- Math: GSM8K, MATH-500, AIME, Minerva-Math;
- Code: HumanEval, MBPP, LiveCodeBench, BigCodeBench;
- Chinese: C-Eval, CMATH, CMMLU, IQuiz;
- Long context: LongBench-v2, FRAMES, Needle-in-a-Haystack;
- Instruction following, agents, tool calling, QA and truthfulness.

## UI flow

The evaluate-only job page (`/new/eval`) consists of three sections:

1. **Checkpoint**: quantized path, quantization format, and optional base model and tokenizer;
2. **Evaluation datasets**: select a suite (quick check, standard or custom), a category and a dataset; review metrics, sample count, language, tags and documentation; then add it to the run;
3. **Optional deployment and benchmarking**: expand when EvalScope execution or throughput measurement is required.

Dataset selection uses hierarchical "suite → category → dataset" dropdowns, presents selected datasets in a compact list, and keeps the detail card focused on the current dataset.

## Job specification

Offline benchmarks are configured under `evaluation.benchmarks`:

```yaml
evaluation:
  dataset: wikitext-2-raw-v1:test
  seq_len: 512
  max_windows: 40
  benchmarks: [wikitext2_ppl, smoke_qa]
  limit: 50
```

EvalScope datasets are configured under the deployment section:

```yaml
deploy:
  vllm:
    evalscope:
      datasets: [gsm8k, ceval]
      limit: 100
      eval_batch_size: 8
```

## Reports

Reports present the following for each dataset:

- metric (PPL or accuracy) and sample count;
- runtime;
- accuracy by `subject` category;
- skip reason (for example, a checkpoint format that cannot be loaded offline);
- EvalScope metrics after deployment.

## Adding an offline benchmark

1. Add a JSONL file under `data/datasets/`;
2. Add an entry to `benchmarks.yaml` with `kind`, `metrics`, `group`, `language` and `source`;
3. Register it in `eval_suites.yaml` if it belongs to a suite;
4. Run `PYTHONPATH=python pytest python/tests -q`.

Adding an EvalScope dataset requires only an entry in `evalscope_catalog.yaml` (or re-running the generator); no C++ or frontend changes are needed.
