# Web 界面导览

**状态：已实现**（React + TypeScript + ECharts，由 `mqde serve` 托管）。界面文字是**中文**（项目规则要求 zh-CN / en-US 国际化，但英文文案尚未提供）。截图来自一个有已完成作业的运行实例；模型路径输入框已被裁掉。

左侧边栏把页面分组：*评估前*（部署预评估、模型结构、资源预估）、*量化与评测*（新建作业、作业与执行、配方对比）和*部署*（硬件与后端、模型目录）。底部有深色/浅色主题切换。

## 部署预评估

路由 `/fit`。目标系统面板（硬件画像、GPU 数量、系统内存、并发、上下文、用途）驱动一张按模型库排序的表：参数量、适配等级（完美 / 良好 / 勉强 / 太紧）、运行模式、最佳量化、显存、速度和评分。选中一行会显示评分构成（质量、速度、适配、上下文）、关键指标和跨硬件规划。这就是带图形界面的 `mqde fit`，见 [预估](estimate.md)。

```{figure} ../../_shared/img/fit.png
:alt: 部署预评估页
:width: 100%

部署预评估页：上方是目标系统，中间是模型排名，下方是评分构成与跨硬件规划。
```

路由 `/graph`。类 netron 的浏览器：组件、块、模块、张量。节点颜色表示算子类型；点击节点可以看到它的张量、数值直方图和针对所选配方的量化误差预览。支持本地模型和 Hub 模型（只读头部，不下载权重）。

```{figure} ../../_shared/img/graph.png

一个视觉-语言-动作模型的结构：左侧是层级树，中间是单个块的前向图，右侧是属性面板。
```

## 新建作业

路由 `/new`。选择模型类型（VLA 或 LLM）、配方（实验性配方有标注）、算法（默认使用各配方的默认算法）、评估数据和目标硬件。LLM 作业的表单还提供静态激活、KV Cache 量化、混合精度、导出格式、llama.cpp 类型和敏感度分析。底部的 **JobSpec 预览**就是“提交作业”会 POST 到 `POST /api/v1/jobs` 的 JSON，也就是你可以手写的 [作业配置](job_spec.md)。

```{figure} ../../_shared/img/new-job.png
:alt: 新建作业表单中的量化配方与算法部分
:width: 100%

配方与算法选择（其上方的模型路径输入框未显示）。
```

## 作业列表与作业页

路由 `/jobs` 列出 `--runs` 目录中的所有作业（包括从命令行启动的），显示状态、类型（LLM/VLA）、当前阶段、配方、设备和耗时。

```{figure} ../../_shared/img/jobs.png
:alt: 作业列表
:width: 100%

作业列表：7 个 LLM 作业和 4 个 VLA 作业；一个失败的作业以红色显示。
```

作业页（`/jobs/<job-id>`）从上到下包括：

- **执行过程**（阶段流水线，按状态着色，带耗时和重复次数）与由事件流驱动的**实时日志**；
- 摘要卡片：基线 PPL、评估 token 数、校准窗口、模型块数与线性层数；
- 标签页：**总览**，以及每个配方一个**误差分析**页（按块和层类型的逐层误差热力图（SQNR dB）、各块平均 SQNR、误差对激活峰度、误差最大的 15 层，以及敏感度结果和“按建议生成新作业”按钮）；
- 三个评估位点的 **PPL 图**，以及**配方汇总**（算法、规格、PPL、相对原模型的变化、KV 增量、量化/跳过的层数、耗时、最差层）；
- **真实低比特导出（S09）与伪量化/真实一致性（S10）**表；
- **vLLM 部署（S11）与部署后精度（S12）**表，和/或 **llama.cpp 部署**图表。

## 硬件与后端、模型目录

`/hardware` 显示 C 探针发现的设备（含作业池状态）和硬件画像库；`/catalog` 搜索本地 Hugging Face 模型目录和在线 Hub，并在预算内下载权重（服务器需要网络，主机没有网络时需要代理）。两者都是普通表格，且会暴露主机的细节，所以这里不配图。
